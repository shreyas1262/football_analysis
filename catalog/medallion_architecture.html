The Medallion Pipeline

FBref data moves through three tiers before it's queryable — bronze, silver, gold — named for the medal podium, each tier a little more refined than the last. Here's what's built, what's tested, and what's still ahead.

The mechanism

The three tiers

Bronze

built

The raw catch — exactly what FBref returned, reshaped just enough to write to disk. Nothing renamed, nothing filtered, nothing dropped.

Tool
PySpark + delta-spark
Format
Delta Lake (Parquet + transaction log)
Location
data/bronze/
Scope
17 tables · Big 5 · 2024–25
  • Written by soccerdata/ingest.py — scrapes FBref via soccerdata, converts pandas → Spark, writes partitioned Delta.
  • CDC via two strategies: fact tables get dynamic partition overwrite (only touches ingested league/season partitions); dimension tables (leagues, seasons) get a MERGE so re-runs update rather than wipe.
  • Season codes are multi-year for the Big 5 ("2425" = 2024–25) — a single-year code like "2022" silently resolves to the wrong season.

Silver

built & tested

Bronze, made trustworthy — typed, renamed to one consistent vocabulary, keyed, and checked with dbt tests. Still one model per source table; no joining across families yet.

Tool
dbt-duckdb, reading Delta via delta_scan()
Materialization
views, in data/warehouse.duckdb
Models
16 stg_fbref_* models
Coverage
28,555 rows · 34/34 tests passing
  • Three join keys carry the whole layer: match_id (FBref's own hash, pulled from the match URL), player_id (surrogate hash of player+born+nation — messy natural key, so hashed), and team_id + season (a clean composite, left as-is).
  • Team-match rows are kept only when their match_id exists in the schedule — gating on the unreliable league string first had silently dropped 310 real league matches.
  • Match dates come from the game string, not the bronze date column — that column is a tz-shifted timestamp and date::date was off by a day.
  • Player and team model vocabularies are reconciled to one naming convention (save_pct, minutes_90s, penalties_allowed, …) so gold-layer joins won't fight column-name drift.

Gold

designed, not built

The payoff layer — a star schema built by joining silver models together, wide enough that one row answers a real question ("how did Bruno Fernandes' 2023–24 compare to Scholes' 2002–03").

Tool
dbt-duckdb (same warehouse, new layer)
Shape
dimension + fact tables
Status
modeled in conversation, not yet written
  • dim_players, dim_teams — one row per entity, keyed by the silver surrogate/natural keys.
  • fct_player_season_stats — left-joins all five player-season models (standard, shooting, keeper, playing_time, misc) on player_id; keeper is a left join since only ~7% of players are goalkeepers.
  • fct_match_results — one row per match, built from schedule plus both teams' match-stat rows.

Decisions worth remembering

NaN is a string bronze

Bronze stringified pandas NaN, so nulls read back as the literal text 'nan'. Filter with != 'nan' — IS NOT NULL silently does nothing.

Surrogate vs. natural keys silver

Hash a key only when the natural one is messy (players: name collisions). When it's already clean and small — team_id + season — a composite key beats an opaque hash.

Gate on the trustworthy table silver

The bronze league column lies for real league matches. Filtering match-level tables on schedule membership instead of that column recovered 310 matches a naive filter had dropped.

DuckDB to build, Postgres to serve

DuckDB reads Delta natively and is fast for the analytical transforms dbt runs. Postgres is for the concurrent, always-on serving hop the MCP server needs later — different jobs, not a rivalry.

Where to pick up

  1. Ingest more history. Only 2024–25 is loaded — ingest.py --seasons … for prior years is the unlock for any era comparison. Note: FBref's advanced stats (xG, pressures) only exist from roughly 2017–18 onward.
  2. Build the gold layer. Start with fct_player_season_stats — the wide join that makes Scholes-vs-Bruno a single query.
  3. Redeploy the serving layer. The mcp-touchline / mcp-touchline-dev Fly machines were destroyed to stop idle billing; apps and secrets are intact, so fly deploy brings them back once gold + Postgres are ready.
